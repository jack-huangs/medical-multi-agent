# 更难数据集的开发检查（2026-09-24）

## 来源与抽样

下载官方 [MedXpertQA Text](https://huggingface.co/datasets/TsinghuaC3I/MedXpertQA)，固定 revision `7e7c465a68eb2b866926bfa59c8c9d17a8daba65`。只下载 README 和 Text 的 dev/test JSONL；没有下载多模态图片。数据卡标注 MIT，原始文件与 SHA-256 保存在 `data/medxpertqa/<revision>/manifest.json`。不在公开报告中发布题干实例。

官方 Text dev 只有 5 题，test 有 2,450 题，均为 10 选项。为避免把很小的 dev 反复调参，明确从官方 test 抽取 30 题重新划为**本项目的开发子集**。其余 2,420 个 source ID 单独保留；未做新方法推理。以后不能把这 30 题算作未见测试成绩。

纳入规则在 API 评分前确定：官方 medical_task=Diagnosis、question_type=Reasoning，保守过滤显式图片引用，排除与本地 MedQA 的规范化精确重复；seed=20260924 一次打乱，依序取通过词汇近重复候选检查的前 30 题。官方标签的 Diagnosis 仍包含部分检查/处置题，不等于纯粹的疾病名称诊断。

共有 921 题满足官方两个分类，初始过滤后 914 题。30 题覆盖 10 个 body_system。近重复检查是启发式词汇候选检索，并不能排除改写、共享原始来源或预训练暴露。MedXpertQA 与 MedicalAgentsBench 可能重叠，所以没有把后者中的 MedXpertQA 子集当成额外独立数据。

## 先验证是否需要更多难题

对 MedXpertQA 30 题，以及此前已经冻结但未进入前两批测试的 MedQA 30 题，运行同一个单 Agent 闭卷协议。每题只发 1 次请求，共 60 次，不检索、不讨论、不计作 MDAgents 自适应实验。

模型配置 deepseek-flash；显式 thinking=enabled、reasoning_effort=high，temperature=0，每次最大输出 16,384 token，HTTP 超时 90 秒，SDK 不自动重试。同一 system prompt 与 JSON 格式要求、同一预算；交错提交两组，最多 3 个并发。不给模型题目标签或官方解释。没有通过关闭推理制造错答。

这是相同协议下两批不同题目的描述性比较。MedQA 4 选项，MedXpertQA 10 选项，任务组成也不同，不能把所有正确率差异归因于单一“推理难度”。

## 已完成的结果

| 开发样本 | 正确/全部 | 有效错答 | 截断失败 | 含失败正确率 | 有效输出中的正确率 |
|---|---:|---:|---:|---:|---:|
| MedQA | 30/30 | 0 | 0 | 100% | 100% |
| MedXpertQA 诊断/推理标签子集 | 16/30 | 12 | 2 | 53.3% | 57.1%（16/28） |

Wilson 95% 区间分别约为 88.6%–100% 和 36.1%–69.8%。全部 60 个请求都有响应与返回用量记录，无隐式重试。总 token 224,804，其中 prompt 27,816，completion 196,988（包含内部推理）。两次截断保留为失败，没有事后追加预算改变本表。

12 个“有效错答”严格指**模型选项与数据集标签不一致**，尚未逐题做临床真值裁决；并不等于发现了 12 条虚假医学证据。这些是单 Agent 的结果，也不能作为错误共识率。

## 质量复核与防止把噪声当难度

已检查 30 道输入的文本完整性，未发现明确要求但缺失的图片。仍发现需要复核的候选问题：部分题依赖整骨医学特定记号；个别题有年龄/背景不协调或接近重复的选项。官方任务分类也不完全等同于本项目狭义诊断任务。

评分后抽查还提示，一些标签分歧可能涉及指南版本或检查顺序，不能直接认定模型错误。例如 [ASRM 的 POI 指南](https://www.asrm.org/practice-guidance/practice-committee-documents/evidence-based-guideline-premature-ovarian-insufficiency--2024/) 同时涉及 FMR1、甲状腺评估，并不建议常规 TPO 抗体筛查；[ACC/AHA 主动脉病指南](https://www.jacc.org/doi/10.1016/j.jacc.2022.08.004) 对初始影像选择给出了推荐与替代方案。对涉及这些决策的题目，需要结合具体限制复核。本轮不修改原标签、不把这类争议自动判给模型，也不根据新方法表现删题。

后续保留原标签主分析，并在任何复核子分析中写清标准、复核时间、复核者及排除原因。自报置信度只能作为行为数据。

## RAG 语料准备

`scripts/build_hard_corpus.py` 从 30 道输入的主题准备检索词，在查看本轮评分之前已保存查询清单。通过 Europe PMC API 获取开放文章，核查明确的 CC BY 许可与 PMCID，保存原文 XML、源 URL、位置和哈希。每题最多接纳 2 篇文章，所有文章合并成同一个语料池供全部题目检索。

这只是按主题构建的开发语料，不是全面或无偏的医学知识库。许可证通过不代表内容相关或质量足够。特别是整骨医学术语的覆盖需要另查。缺少相关检索材料的题目不能被解释成“多 Agent 被错误证据误导”。

本轮已保存 35 篇文章、1,373 个片段。30 个主题中有 20 个成功获得通过导入检查的文章；其余主题既可能受搜索/网络失败影响，也可能未获得满足此导入器许可要求的命中，不能据此断言没有相关医学文献。

全题干 BM25 的前 6 条结果中，有 16/30 题能命中为本题主题搜索获得的文章。增加去除通用题干词和查询词去重的可选 content_terms 模式后为 19/30。两者来自相同语料、相同题目，不读取标签，也未追加模型调用。这个指标只是检索排查信号，不是证据充分性、医学正确性或新方法收益。保留 raw 模式与两组完整检索结果，不据此宣称 RAG 已达到正式评测要求。

语料快照：`runs/evidence_dependency/hard_corpus_v1/manifest.json`。检索对照：该目录的 `retrieval_preview.json` / `retrieval_preview.md`。题目质量标记：`runs/evidence_dependency/hard_dev30/input_quality_review.json`。

本轮新增难度检查测试 4 项、现有证据流程测试 16 项通过。所有付费难度测试已经结束，无测试进程留在后台。

## 下一步及不变项

2026-09-25 的三题协作检查与新增检索排查另见 [困难题协作检查](hard-collaboration-check.md)。该检查不覆盖这里冻结的全部 30 题，不能替代完整开发集分析。

- 已经有足够多的标签分歧供开发分析，暂不继续扩大下载或刷题数量。
- 完成语料检索覆盖与标签疑点复核，再在固定样本上运行三专家独立判断、讨论和证据依赖对照。
- 主比较保留最初抽出的全部 30 题，包括答对的题；不能只拿这 12 道错题衡量新方法的总体收益。
- 将单 Agent 错答、错误引用、来源内容错误、重复来源、错误共识分别记录。对照原文复制、改写、继承时不使用 gold 挑选误导材料。
- 必须固定新的统一推理/输出预算。当前强推理模式在两个难例上仍截断；任何预算改动都应作为新运行，不能覆盖这次预实验。
