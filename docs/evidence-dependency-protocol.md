# 证据依赖感知协作：开发协议 v0.1

日期：2026-09-23。状态：工程原型，尚未完成有效性验证。方法、语料与正式统计方案尚未冻结为论文实验。

## 研究问题与可证伪的假设

同一外部证据被重复传播后，多位 Agent 的一致意见可能仍只有一个证据来源。研究问题是：在保留原有证据的情况下，重复传播是否增加错误共识，来源依赖处理是否比简单去重更有效。

- H1：普通协作在重复传播条件下，相比原始条件，更容易产生错误共识或由对变错。
- H2：相同重复传播条件下，依赖感知处理可以减少这种变化。
- H3：收益超过简单文本去重与相当资源的单 Agent。若不能超过，应收窄主张。
- H4（后续）：改写、跨 Agent 继承与来源缺失时，依赖估计仍有效。当前实现不验证这个假设。

这些是假设，不是已有实验结论。LangChain、LangGraph、RAG 接入本身不构成论文创新。

## 与旧实验的关系

旧 MDAgents 实验仍采用模型决定 basic/intermediate/advanced 的自适应路由。已保存的两批 100 题均走 basic，不能测量多专家错误共识。

这里使用明确的固定三专家机制实验，入口与旧实验分开。没有修改旧路由使其强制多专家。未来方法有效后，再研究它何时应该被自适应触发。

第二批旧实验存在续跑重叠与日志计数不一致。新审计区分路由一致性与单次运行完整性。97/100 仅描述已保存的答案，不作为该批过程、成本可靠的正式证据；原始日志与答案保留。新的进程锁不能追溯修复旧记录。

## 样本

使用原 reserve_200 的后 100 个输入，从中依序选出通过预先声明的视觉引用过滤规则的前 30 个。它们未进入前两批 200 题，没有根据正确率挑题。

输入、标签和选择清单位于 `runs/evidence_dependency/dev30/`。选择规则只访问输入；评分单独读取标签。30 个输入已逐一检查：未发现明确依赖缺失图片的要求。此检查由编程助手完成，不是医生复核。保留原始单位、题目措辞与标点问题，不以模型答对答错作纳入标准。

这些是开发题，不是临床病例验证，也不是官方测试集。正式研究需要冻结方法后使用独立留出数据，并处理跨数据集重叠与可能的预训练暴露。

## 实际实现

LangGraph 编排：检索 → 三个互不可见的独立请求 → 四种配对条件 → 单 Agent 对照。LangChain 的 Document/BaseRetriever 提供文档与检索接口，BM25 作为无 embedding API 成本的首个 RAG 基线。

同一病例仅生成一套初始意见，四个条件复用完全相同的初始意见和检索结果，并记录其哈希。条件执行顺序按病例 ID 确定性打乱。每次请求是独立上下文，温度 0 不被视为服务端确定性的保证。

| 条件 | 原始证据 | 重复送达槽位 | 依赖信息 |
|---|---|---|---|
| original | 完整保留 | 空白占位 | 无额外账本 |
| repeated | 完整保留 | 原文复制三次 | 无额外账本 |
| dedup | 完整保留 | 文本规范化去重后占位 | 无额外账本 |
| dependency | 完整保留 | 与 repeated 完全相同 | 根来源映射、观点继承与去重账本 |

目标片段按病例 ID 与 chunk ID 的哈希选择，不访问标签、Agent 预测或证据对错。重复片段使用原证据 ID，不伪造新专家背书，也不挤占原始检索证据。这是讨论阶段的重复送达，不是检索阶段排挤实验。

original 和 dedup 在“完全相同原文复制”条件下会得到相同的模型输入，是刻意保留的检查。仅在这个条件胜出，仍不足以支持超越简单去重的创新主张。

空白占位只匹配字符长度，**尚未匹配 tokenizer token 数**。来源账本也增加输入长度。因此此版只能测试机制与接口，不能声称已控制所有长度、位置和计算预算混杂。正式比较需增加 tokenizer 长度控制、位置轮换、长度匹配的无关元数据对照、正确/打乱 lineage 对照、只有提醒提示词的对照，以及表层近重复去重基线。

每个多专家条件逻辑上有 3 个初始、3 个修订、1 个汇总请求。配对执行共享初始三次，四组共 19 次；单 Agent 7 次自检，共最多 26 次/题。单 Agent 对照只匹配调用数与输出上限，**尚不是严格 token/金额匹配的强基线**。30 题上限为 780 次请求；未全部启动。

## 证据和继承语义

每段证据保存 document_id、chunk_id、source_url、license、locator、text、内容哈希及 root_id。默认 root_id 为片段标识，不把整篇论文当成一条信息。已知复制或已核验的改写可共享 root_id。不同 root_id 不意味着来源统计独立；不同论文还可能引用同一原始研究，这一版尚不能识别。

Agent 输出选项、简短依据、自报置信度和支持/反驳的 claim。外部 claim 必须引用存在的 evidence_id 和可在原文定位的引用，或继承已有 parent_claim_ids。程序沿父观点传播 root_id，Agent 无权直接生成新的根来源。

账本按“选项、支持/反驳关系、已知根片段”归组，每组只计一次来源贡献，并保留不同 claim 文本和所有传播节点。同一片段支持不同选项或同时支持/反驳不会被抹掉。汇总模型收到去重账本与判断规则；当前不是经过学习或验证的依赖概率模型。

引用字符串存在不证明医学结论被原文支持。父观点继承依赖模型如实标注；未标注的暗中抄袭尚未自动检测。后续需要单独评价 claim 对齐、引用蕴含与依赖边识别，而不能把引用检查通过率当作事实正确率。

## 语料和执行范围

`examples/evidence_dependency/` 只有明确标记的虚构分类资料，用于离线测试；live 模式拒绝该语料。医学语料应使用有可复用许可的真实文献或教材，保留版本、原文位置与许可证。PMC 的开放子集并非全部 PMC 文章，需逐文核查许可证，并使用支持的获取接口。

单题医学连通性检查可以使用针对题目主题选取的小型语料，但必须声明这是人工选材的调试，不能当作统一语料检索基准。30 题正式开发运行前要建立覆盖这些题目主题的统一语料快照，检查检索结果和引用质量。

## 运行完整性与成本

- 控制器和每道题都有操作系统锁，进程退出后自动释放；不通过删除锁文件解锁。
- 每次尝试使用独立 UUID 目录，日志只追加，不覆盖历史尝试。运行保存源码、语料/输入哈希、包版本与配置；变更配置后必须换目录。
- 已完成题恢复时不重复请求。失败题默认保留，只有显式 retry-failed 才重试，并保留所有尝试成本。
- 每个请求先记录开始，再记录原始响应、模型标识和返回用量。无 SDK 隐式重试。请求超时或进程退出可能造成账单未知，单独标记而不估计成零。
- 每次调用上限默认 2048 输出 token，超时 90 秒；每题最多 26 次。格式或引用验证失败不会静默改写或免费重试。
- 本地运行关闭 LangSmith 自动上传。凭据沿用项目 .env，但不会写入实验快照或日志。

## 指标与解释

离线评分按原始病例输出配对表，包含最终正确率（失败保留在分母）、由对变错/由错变对、三位修订专家的一致率、错误一致数/全部题数、错误一致数/一致题数、自报置信度变化，以及实际调用和返回 token。

最终汇总 Agent 的答案与三位专家是否一致是不同变量。单 Agent 没有多专家共识指标。没有一致样本时，条件错误率记为不适用。缺失答案不混入“有效答案由对变错”，其数量单列。

开发阶段报告描述性结果。正式阶段应在原始问题层面做配对推断/分组 bootstrap；不能将同一病例的四种处理、复制次数或随机重复当成独立病例。样本规模需根据开发效应与配对不一致率预先估算，不能不断加题直到显著。

## 执行方式

在项目根目录使用隔离环境，避免改变旧 MDAgents 的依赖：

```powershell
$py = '.\runs\evidence_dependency\.venv\Scripts\python.exe'
& $py -m pip install -r requirements-evidence.txt
& $py -X utf8 scripts/test_evidence_pilot.py
& $py -X utf8 scripts/run_evidence_pilot.py --backend fake --inputs examples/evidence_dependency/inputs.jsonl --corpus examples/evidence_dependency/corpus.jsonl --run-dir runs/evidence_dependency/offline_smoke --top-k 3
& $py -X utf8 scripts/score_evidence_pilot.py runs/evidence_dependency/offline_smoke --labels examples/evidence_dependency/labels.jsonl
```

真实语料使用 JSONL，每行必需字段见 fixture。只向 runner 传 inputs，labels 仅传给 scorer。医学 API 调试使用 `--backend deepseek`，真实模型名来自 `.env`；聊天助手模型切换不会改变它。

单题真实连通性调试使用 [Depression and Sleep](https://pmc.ncbi.nlm.nih.gov/articles/PMC6386825/) 的 CC BY 原文，导入后有 39 个片段。该篇文献是按第一道开发题主题选取的调试资料，不能用作覆盖 30 道题的统一医学语料库。

实际调试发现，当前后端的推理 token 也会消耗输出上限：2048 上限下出现 JSON 截断；4096 上限下有一例全部用于内部推理，返回空内容。截断保留为失败，不在解析器中伪造补齐。`resume_evidence_debug.py` 可复用来源明确、完整且请求完全相同的响应，仅补未完成阶段，并单独记录新调用。因提高了后续请求预算，该模式只能用于连通性调试，不能充当相同预算的科学比较。正式实验前应固定统一预算与失败处理规则。

## 下一阶段的完成标准

1. 医学单题真实 API 能完成结构化输出、合法引用与四组配对，且成本记录自洽。
2. 统一语料覆盖检查完成后，再运行冻结的 30 道开发题，不以“出现了几个错题”作为成功标准。
3. 评估错误共识是否出现、重复干预是否足够强、简单去重是否已解决问题。
4. 再扩展到改写/跨 Agent 继承/隐藏来源，区分已知来源上界和实际依赖估计，加入消融与严格预算控制。
